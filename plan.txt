📦 v3.0.0-PRO 核心架构升级计划
1. 独立飞书文生图系统 (Asset-T2I System)
将原有的【素材生成表】（tbloUrdwqG47ZmgI）升级为独立的资产配置中心，不再仅仅是回填 URL。
物理存储分区：
资产库 (Master Library)：存储角色的“三视图/基准图”和场景的“概念图”。
衍生库 (Variant Cache)：通过 entity_id 关联，存储基于基准图进行 I2I（图生图）演化后的特定分镜图。
状态机增强：
引入 Version_Tag (如 v1.0-Basic, v1.1-Injured)。
引入 Visual_Seed：锁定随机种子，确保同一实体在不同分镜间的视觉一致性。
2. 分镜分区与防覆盖存储逻辑 (Storyboard Partitioning)
痛点：目前分镜在 stage2 生成后容易在多次迭代中被覆盖，且缺乏历史版本溯源。
方案：
复合主键索引：在【剧本拆解表】中，分镜记录的存储键由 (novel_id + chapter_id + scene_index + version_timestamp) 组成。
分区管理：
Draft Zone (草稿区)：DeepSeek 初次生成的原始分镜文字。
Frozen Zone (冷冻区)：一旦生成视频任务启动，分镜内容自动转入只读状态，其对应的 visual_prompt 和 image_url 建立永久链接。
动作：在 FeishuBitableManager 中新增 archive_used_storyboard 方法，防止旧分镜被后续流水线更新覆盖。
3. 多分镜 I2V 提示词优化 (Multi-Frame Prompting)
为了让 10s 视频更丰富，我们需要打破“一张图到底”的局限。
多帧锚点注入：在 stage4_video_gen 中，支持读取多个 storyboard_images。
Prompt 拓扑结构：
Markdown
[PROMPT_STRUCTURE]:
Initial Frame: {{image_url_1}} (固定起势)
Key Movement: {{dynamic_description}} (由 DeepSeek 拆解的剧烈动作)
Transition Target: {{image_url_2}} (作为演化目标的第二分镜图)
[VIDEO_CONFIG]: duration=10s, consistency_weight=high
逻辑处理：修改 RenderProtocol，使其能承载 List[ImageURL]，并适配火山/阿里 API 的首尾帧控制接口。
4. 图片间场景/任务的衍生 (I2I Derivation)
打通“基准图 -> 分镜图”的衍生链路，实现视觉层面的“固定与演进”。
衍生算法流程：
取样：从素材表提取 entity_id 的基准图 URL。
垫图生成 (Image Prompting)：调用 ImageService (Pollinations/Flux)，将基准图作为 ref_image 传入。
增量控制：在生图 Prompt 中仅加入动作变量（如："{{base_lore}}, holding a sword, running in rain"），同时设置 image_strength=0.6（保持 60% 的原始视觉特征）。
解耦实现：新建 core/services/image_service/derivation_engine.py，专门负责这种“基于引用的资产演化”。
